# Тестовый прототип анализа изометрий

Это тестовое локальное приложение для разбора PDF с изометриями трубопроводов. Целью было полностью решить задачу: найти линии, размеры, вершины, элементы чертежа и подготовить данные для расчета длины трубопроводов и проверки человеком.

До конца довести расчет длин не успел. Основные наработки, которые уже можно проверять, находятся на этапах **«Локальная обработка»** и **«Расчет длины трубопровода»**. Локальная обработка находит числа, координаты, базовые вершины, осевые ребра, размерные кандидаты, часть штурвалов/арматуры и формирует диагностические PDF-разметки. Расчет длины пока является экспериментальным слоем поверх этих локальных данных.

## Что уже умеет

- Загружать PDF и группировать листы по линиям.
- Показывать найденные линии и страницы.
- Находить на листе:
  - размерные числа;
  - координаты X/Y/Z;
  - базовые вершины `V`;
  - исходный контур/ребра трубы;
  - размерные кандидаты;
  - локальные решения `include / exclude / ambiguous`;
  - часть штурвалов/арматуры.
- Строить диагностические PDF:
  - разметка чисел;
  - вершины;
  - координаты;
  - размерные кандидаты;
  - локальная фильтрация размеров;
  - диагностический PDF для расчета длины.
- Экспортировать результаты в JSON и Excel.
- Показывать историю запусков, время запроса провайдера и токены, если они вернулись от провайдера.
- Показывать прогресс анализа без загрузки тяжелого payload на каждом обновлении страницы.
- Запускаться локально или через Docker Compose на VPS.

## Что с расчетом длины

Этап **«Расчет длины трубопровода»** находится в экспериментальном состоянии.

Что он уже пытается делать:

- берет локально найденные размерные кандидаты;
- сохраняет локальные решения без автоматической замены;
- отправляет провайдеру данные по листам отдельными запросами;
- просит провайдера проверить локальные решения;
- отдельно помечает возможные смежные длины с других листов;
- показывает локальный расчет и подтверждение провайдера отдельными колонками;
- позволяет вручную принять решение провайдера или оставить локальное решение.
- считает локальную сумму на стороне приложения, а ответ провайдера показывает отдельно как проверку/предложение;
- выгружает в Excel локальные решения, сравнение с провайдером и итоговые значения.

Что пока не гарантировано:

- корректный расчет длины всей линии по нескольким листам;
- надежное разделение основного маршрута и ответвлений;
- автоматическое склеивание продолжений между листами;
- стопроцентное определение размеров штурвалов;
- финальная полнота Excel-выгрузки как производственного результата.

Иными словами: длины сейчас стоит рассматривать как диагностическую заготовку, а не как завершенный расчет.

Старый этап **«Карта размеров + проверка провайдером»** сейчас оставлен в коде и истории, но в интерфейсе заблокирован для запуска. Основной путь проверки — **«Локальная обработка»** и экспериментальный **«Расчет длины трубопровода»**.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Открыть в браузере:

```text
http://127.0.0.1:8000
```

Если окружение еще не установлено:

```powershell
python -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements.txt
```

Для AI-провайдера DeepSeek нужен ключ в `.env` или переменных окружения:

```text
DEEPSEEK_API_KEY=...
DEEPSEEK_MODEL=deepseek-flash
```

## Запуск через Docker Compose

Для VPS можно запускать приложение как один контейнер. Перед запуском создать `.env` рядом с `docker-compose.yml`:

```text
DEEPSEEK_API_KEY=...
DEEPSEEK_MODEL=deepseek-flash
AI_PROVIDER=deepseek
APP_PORT=8000
PIPELINE_WORKERS=4
PIPELINE_LENGTH_MAX_TOKENS=32000
PIPELINE_LENGTH_DEEPSEEK_TIMEOUT=120
```

Запуск:

```bash
docker compose up -d --build
```

После запуска открыть:

```text
http://<ip-vps>:8000
```

Данные прогонов, загруженные PDF, SQLite-база и артефакты сохраняются в Docker volume `app_cache`, поэтому не пропадают при пересоздании контейнера. Остановить приложение можно командой:

```bash
docker compose down
```

## Короткий UX для проверки

1. Открыть приложение.
2. Нажать **«Загрузить PDF»** или использовать дефолтный `isometries.pdf`, если он есть в папке проекта.
3. Дождаться списка найденных линий.
4. Выбрать одну или несколько линий.
5. В поле **«Делать до этапа»** выбрать нужный этап:
   - **«Локальная обработка»** — основной стабильный диагностический этап;
   - **«Расчет длины трубопровода»** — экспериментальная проверка расчетов длины;
   - **«Карта размеров + проверка провайдером»** — старый этап, сейчас в UI временно недоступен.
6. Нажать **«Запустить»**.
7. Открыть результаты по линии и листам.
8. Смотреть PDF-разметки через кнопки артефактов:
   - `numbers_pdf`;
   - `vertices_pdf`;
   - `coordinates_pdf`;
   - `dimensions_pdf`;
   - `pipeline_length_diagnostic_pdf`;
   - другие доступные артефакты.
9. Скачать результаты через экспорт:
   - JSON;
   - Excel;
   - архив review-data, если нужен разбор payload/ответов.

## Что смотреть в первую очередь

Для оценки текущей работы лучше начать с **«Локальной обработки»**, затем отдельно попробовать **«Расчет длины трубопровода»** на одной линии.

Там полезнее всего проверять:

- правильно ли найдены размерные числа;
- где стоят базовые вершины `V`;
- как построен исходный контур трубы;
- какие размеры включены/исключены локальным фильтром;
- где найдены штурвалы;
- какие артефакты можно использовать для ручной проверки.

На этапе расчета длины полезнее всего проверять:

- локальные решения по каждому размеру;
- колонку подтверждения провайдера;
- ручные решения **«принять решение провайдера»** / **«оставить локальное»**;
- блок штурвалов;
- диагностический PDF `pipeline_length_diagnostic_pdf`;
- Excel-выгрузку с локальным расчетом, провайдером и сравнением.

## Производительность UI

Во время активного анализа интерфейс опрашивает легкий endpoint прогресса `/api/runs/{run_id}/progress`. Он возвращает только статусы, последние события и ошибки. Полный результат с тяжелыми `analysis`, payload и provider trace загружается один раз после завершения прогона.

Это сделано специально, чтобы процесс анализа не создавал ощущения, что весь сайт заблокирован.

## Ограничения прототипа

- Это не финальная промышленная версия.
- Локальная геометрия иногда ошибается на сложных пересечениях, ответвлениях и плотной разметке.
- AI-проверка может быть медленной и зависит от размера payload и качества ответа провайдера.
- DeepSeek иногда тратит много токенов на внутреннее рассуждение; для этапа расчета длины используется `PIPELINE_LENGTH_MAX_TOKENS=32000`.
- Ручное подтверждение решений провайдера сделано как диагностический инструмент.
- Расчет полной длины линии по нескольким листам требует дальнейшей доработки.
